## 0. 版本差異與 M0 結論

| 項目     | v1（HTML）       | v3（終端機，SSH）                                        |
| -------- | ---------------- | -------------------------------------------------------- |
| 資料來源 | ptt.cc 網頁      | `ptt.cc` 的終端機畫面（SSH 或 WebSocket）                |
| 登入     | 不需要           | **必須登入**（登入畫面也提供 `guest` 參觀）              |
| 連線     | 無狀態，可並行   | 單一有狀態連線，**指令必須逐一排隊**                     |
| 解析     | CSS 選擇器       | 讀 80×24 螢幕文字                                        |
| 文章識別 | 網址檔名         | 文章代碼（AID）與文章網址，**已驗證**                    |
| 最愛看板 | 本機儲存         | 帳號上的最愛（伺服器端）                                 |
| 新增風險 | Cloudflare、改版 | 帳號安全、重複登入踢線、畫面時序錯位、連線中斷、主機金鑰 |

### M0 實測結論（2026-11-03）

1. **WebSocket 閘道以 `Origin: https://www.ptt.cc` 連線被拒**：`wss://ws.ptt.cc/bbs` 回應 `403 Forbidden`（來源是閘道的 openresty），帶或不帶 `User-Agent` 結果相同。**更正**：`https://www.ptt.cc` 是舊函式庫的預設值，原擴充功能實際使用的是 `https://term.ptt.cc`（`src/extension.ts:27`），其 `CHANGELOG` 0.3.2 記載 PTT 曾更新規則、擋掉沒有合適 Origin 的連線。**補測（同日，依使用者要求）**：以 `Origin: https://term.ptt.cc` 連線**成功**，完整流程（登入、最愛、看板、文章代碼、開文章、登出）與 SSH 的畫面一致。因此「WebSocket 不可用」的說法不成立，只能說「用預設 Origin 不可用」。採用 `term.ptt.cc` 等於以官方網頁終端機的 Origin 連線，是否採用及預設走哪條路徑，見 D11。
2. **SSH 可用**：連到 `ptt.cc` 的 SSH，使用者名稱 `bbsu`，不需密碼即可取得 BBS 登入畫面；畫面預設是 UTF-8。傳輸層以 `Transport` 介面隔離，SSH（`ssh2`）與 WebSocket（`ws`）兩種實作都可行，其餘架構不變。
3. **文章代碼可用**：在文章列表按 `Q` 會顯示文章代碼（AID）與文章網址；在列表輸入 `#` 加代碼可把游標移到該文章。
4. **置頂文的列表標題與內文標題可能不同**：置頂文是指向另一篇文章的連結，因此「標題不符就拒絕」的規則不能套用在置頂文上（見第 5.5 節）。
5. **效能足夠**：SSH 換頁約 120～130 ms（含 60 ms 靜默等待），登入約 1.1 秒；WebSocket 換頁約 64～70 ms（同樣含 60 ms 靜默等待，8 次連續換頁），登入約 1.5 秒。兩者都遠低於需要擔心的程度。

沿用不變的部分：分層原則、領域模型的大部分、PttService 介面、VS Code 檢視與指令、快取設計。

## 1. 目標與範圍

### 1.1 產品目標

在 VS Code 中以帳號登入 PTT，瀏覽最愛與指定看板、閱讀文章。介面貼近開發者習慣：左側樹狀檢視、文章以唯讀文件開啟、可搜尋與複製。

### 1.2 設計原則

1. **一條連線、一個佇列**：所有終端機操作經過同一個指令佇列，一次只跑一個。
2. **每一步都驗證畫面**：送出按鍵後，必須等到「符合預期的畫面」才繼續；不靠固定 `sleep` 判斷成功。畫面不符就失敗，不猜。
3. **未驗證不快取**：讀到的內容通過第 5.5 節的核對後才寫入快取。
4. **核心與 VS Code 分離**：`core/` 不 import `vscode`，才能單獨測試。
5. **帳號安全優先**：密碼只放 `SecretStorage`，不寫入設定、日誌或 fixtures。
6. **不繞過站方限制**：遇到拒絕就回報，不偽裝、不規避。
7. **最小完整**：MVP 只做瀏覽，其他分階段。

### 1.3 功能清單

| 階段     | 功能                     | 說明                                         |
| -------- | ------------------------ | -------------------------------------------- |
| MVP      | 登入與登出               | 帳號密碼存 `SecretStorage`，處理常見登入提示 |
| MVP      | 連線狀態                 | 狀態列顯示連線狀態，斷線可重連               |
| MVP      | 我的最愛                 | 讀取帳號上的最愛看板（唯讀）                 |

| MVP      | 文章閱讀                 | 內文 + 推文，以唯讀文件開啟                  |
| MVP      | 重新整理、複製、清除快取 |                                              |
| 第二階段 | 看板內搜尋               | 標題關鍵字、作者、推文數門檻                 |
| 第二階段 | 設定項目                 | 佇列間隔、逾時、快取時間、重複登入策略       |

## 2. 通訊與畫面（M0 實測，2026-11-03）

### 2.1 連線

| 項目     | 實測結果                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 位址     | `ptt.cc`，埠 22（SSH）                                                                                |
| 使用者   | `bbsu`；驗證方式為 `none`，不需密碼                                                                   |
| 終端機   | `vt100`，80 欄 × 24 列                                                                                |
| 編碼     | **UTF-8**；登入時**不需要**在帳號後加逗號                                                             |
| 主機金鑰 | 本次觀察到 SHA-256 指紋 `a137fbc1…616f18`（完整值見 M1 的設定）；實作要做首次信任並在變更時警告       |
| 登出     | 主選單按 `G`、`Enter`，出現「您確定要離開…(Y/N)？[N]」，輸入 `Y`、`Enter`，再按任意鍵後伺服器關閉連線 |

### 2.1.1 WebSocket 路徑（補測，2026-11-03）

| 項目     | 實測結果                                                                                                          |
| -------- | ----------------------------------------------------------------------------------------------------------------- |
| 位址     | `wss://ws.ptt.cc/bbs`                                                                                             |
| Origin   | **必須是 `https://term.ptt.cc`**（原專案的做法）；`https://www.ptt.cc` 回應 403                                   |
| 編碼     | **預設是 Big5**，以 UTF-8 解碼會亂碼；送出「帳號 + 逗號」後切換成 UTF-8，之後的畫面正常                           |
| 登入     | 流程與 SSH 相同，只是多了帳號後的逗號；不需要 `bbsu` 之類的前置使用者                                             |
| 畫面     | 看板列表、文章列表、文章閱讀、文章代碼訊息框皆與 SSH 一致                                                         |
| 登出     | 與 SSH 相同；結束時連線以 `1000 bbs disconnected` 關閉                                                            |
| 差異提醒 | 啟動畫面（含「請輸入代號…」提示）是 Big5，所以在送出帳號之前的畫面不能用 UTF-8 解析，辨識登入提示時要用 Big5 解碼 |

### 2.2 登入流程（已觀察）

1. 連線後顯示啟動畫面，下方有 **「請輸入代號，或以 guest 參觀，或以 new 註冊:」**
2. 送出帳號與 `Enter` → 出現 **「請輸入您的密碼:」**
3. 送出密碼與 `Enter` → 顯示公告、上次登入的來源位址（含 IP，**fixtures 必須去除**）與 **「請按任意鍵繼續」**
4. 按任意鍵 → 進入 **主功能表**，底部狀態列格式為 `主選單 [..] 月/日 週 時:分 | 帳號 | 線上N人`

**未觸發、未驗證**的分支：密碼錯誤、重複登入提示、頻繁登入限制、刪除錯誤嘗試記錄。這些文字沿用舊客戶端的記錄，M1 以假傳輸測試，並在真實遇到時回寫。

### 2.3 畫面

**我的最愛**（主選單按 `F`，再按 `→`）：標題列 `【看板列表】`，第 1 列是按鍵提示，第 2 列是欄位標題，第 3～22 列為項目，第 23 列是功能提示。欄位固定：編號、未讀標記 `ˇ`、看板名、類別、`◎`、中文敘述、人氣（`HOT`、`爆!` 或數字）、板主。在此清單中按 `s` 只會把游標移到該看板，**不會進入**；按 `→` 才會進入。

**進入看板**：先出現看板進站畫面，底部有 **「請按任意鍵繼續」**，按任意鍵後才是文章列表。

**文章列表**（已在一個看板驗證）：

| 第 3～22 | 文章列，共 20 列；游標列最左邊是 `>` |

- 已刪除文章：作者為 `-`，標題為 `(本文已被刪除) [帳號]`。

**文章代碼**：在列表上按 `Q`，在列表上方浮出訊息框，內容包含：


訊息框底部有「請按任意鍵繼續」，需先送出按鍵才能繼續操作。在列表輸入 `#1gvg4mau` 並 `Enter`，游標會移到該文章（已驗證）。

**文章閱讀畫面**：

- 第 0～2 列：`作者`、`標題`、`時間`（第 0 列右側有 `看板 <名稱>`），第 3 列是分隔線。
- 本文之後有 `--`、`※ 發信站`、`※ 文章網址: <URL>`、`※ 編輯` 等行，接著是推文。推文每行以 `推`、`→` 或 `噓` 開頭，後接帳號、內容與右側的 `MM/DD HH:mm`。
- 底部狀態列：`瀏覽 第 1/2 頁 ( 37%)  目前顯示: 第 01~22 行`。第 2 頁顯示 `第 2/2 頁 (100%)  目前顯示: 第 20~42 行`，也就是兩頁有 3 行重疊，可以用**行號**去重，比對重疊列文字更可靠。第 1 頁的列與行號的對應關係，M2 以更多樣本確認。
- `PgDn` 翻頁；讀到 `100%` 即結束。

**搜尋提示**（已驗證提示文字，結果畫面與離開方式尚未測）：

| 按鍵 | 提示                                        |
| ---- | ------------------------------------------- |
| `/`  | `搜尋標題:`                                 |

### 2.4 解析原則

1. **以儲存格為單位，不以字串索引**：中文與全形符號佔兩欄，用 `@xterm/headless` 的儲存格緩衝區讀取，不自己算寬度。
2. **欄位位置集中**：每個畫面一份常數，驗證後只改一處。
3. **畫面辨識**：每個畫面有一個「辨識條件」（例如特定列出現特定字串），所有步驟都用它確認自己在對的畫面。
4. **缺欄位要明確失敗**：關鍵欄位讀不到，拋出 `unexpectedScreen` 並附上畫面快照（快照不得含密碼，且要去除登入來源位址）。

## 3. 架構

### 3.1 分層

```
VS Code 層（src/vscode/）  ← UI 與 VS Code API 對接
        │
核心服務（core/service）    ← 對外只暴露領域方法，內部排隊執行
        │
screens ─ session ─ commandQueue ─ terminal ─ transport(ssh)
```

### 3.2 目錄結構

```
src/
  extension.ts
  core/
    models.ts
    service.ts              # PttService
    errors.ts
    transport/
      transport.ts          # Transport 介面（測試用假傳輸也實作它）
      sshTransport.ts       # 以 ssh2 連線；主機金鑰首次信任與變更警告
      wsTransport.ts        # 以 ws 連線；Origin 為 term.ptt.cc；登入提示先以 Big5 辨識，帳號後加逗號切換 UTF-8
```

| `ws`              | 採用 WebSocket 路徑才需要 | Origin 須為 `https://term.ptt.cc`（D11）    |

### 3.4 領域模型

```ts
type ArticleId = string; // 文章網址的檔名部分，例："M.1793499440.A.938"

interface ArticleSummary {
  board: string;
  listNumber?: number; // 列表上的編號；置頂文沒有。會隨刪文改變，只當暫時位置
  title: string;
  author: string;
  date: string; // 原樣保留，無年份
  push: string; // 原樣保留
  mark: string; // 欄位 8 的標記
  kind: 'normal' | 'reply' | 'deleted';
  isPinned: boolean;
  id?: ArticleId; // 需要 Q 一步才取得；取不到時為空
  aid?: string; // "#1gvg4mau"
}

interface BoardPage {
  board: string;
  articles: ArticleSummary[]; // 新到舊
  pinned: ArticleSummary[];
  hasOlder: boolean;
}

  kind: '推' | '噓' | '→';
  userId: string;
  content: string;
  dateTime: string; // "MM/DD HH:mm"
}

interface Article {
  id?: ArticleId;
  aid?: string;
  board: string;
  title: string;
  author: string;
  time: string;
  bodyLines: string[];
  pushes: Push[];
  url?: string; // 本文中的「文章網址」行
}

  kind: 'board' | 'folder' | 'divider';
```

### 3.5 核心服務介面

```ts
interface PttService {
  readonly state: SessionState; // disconnected | connecting | loggingIn | ready | error
  onStateChange: Event<SessionState>;

  login(credentials: Credentials, options?: LoginOptions): Promise<void>;
  logout(): Promise<void>;

  getFavorites(): Promise<FavoriteEntry[]>;
  openBoard(name: string): Promise<boolean>; // 進得去才回傳 true
  getBoardPage(board: string, cursor?: PageCursor): Promise<BoardPage>;
  resolveArticleId(ref: ArticleRef): Promise<ArticleSummary>; // 以 Q 取得 AID 與網址
  getArticle(ref: ArticleRef): Promise<Article>;
  search(board: string, query: SearchQuery): Promise<BoardPage>; // 第二階段

  invalidate(board?: string, id?: ArticleId): void;
}
```

### 3.6 傳輸、佇列與等待

| 元件         | 設計                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| transport    | `Transport` 介面：`send(bytes)`、資料事件、關閉事件。`sshTransport` 以 `ssh2` 開 shell，`pty` 為 `vt100`、80×24  |
| 主機金鑰     | 首次連線記錄指紋到 `globalState`；之後指紋不同就拒絕連線並提示使用者（V16 結案前不內建固定指紋）                 |
| settle       | 收到資料後，連續 N ms 沒有新資料才視為一批。預設 80 ms，可設定（M0 以 60 ms 做延遲量測，提早與一秒後的畫面一致） |
| commandQueue | Promise 鏈，一次只執行一個指令；任何指令失敗不得讓佇列卡住                                                       |
| waitFor      | `waitFor(predicate, { timeoutMs })`：每次畫面更新後檢查條件，符合就回傳，逾時就拋 `timeout` 並附畫面快照         |
| resync       | 發生非預期畫面時，連按 `←` 回到主選單，再依需要重新導覽；最多重試 1 次，仍失敗就回報錯誤                         |
| 錯誤種類     | `network`、`timeout`、`loginFailed`、`kicked`、`tooFrequent`、`hostKeyChanged`、`unexpectedScreen`、`parse`      |

### 3.7 快取

- 記憶體 TTL 快取，不寫磁碟。
- 建議時間：最新頁 60 秒、舊頁 10 分鐘、文章 5 分鐘、最愛 5 分鐘。
- 鍵：`board:<name>:page:<cursor>`、`article:<board>:<id>`、`favorites`。
- 同一個鍵的並行請求合併成一次排隊。
- 手動重新整理清除對應鍵；登出時全部清空。

## 4. 登入與帳號安全

### 4.1 憑證處理

| 項目     | 做法                                                               |
| -------- | ------------------------------------------------------------------ |
| 儲存     | `context.secrets`（SecretStorage），鍵含帳號名                     |
| 輸入     | `showInputBox({ password: true })`，不放進設定檔                   |
| 日誌     | 任何日誌、錯誤、畫面快照都不含密碼；送出密碼的那一步不記錄按鍵內容 |
| 畫面     | 畫面快照要去除登入來源位址、帳號等個人資訊                         |
| fixtures | 錄製或整理 fixtures 時以腳本去識別化，並有測試守住                 |
| 移除     | 提供「清除已儲存的帳密」指令                                       |
| 自動登入 | 預設關閉；開啟後才在啟動時使用已儲存的帳密                         |

### 4.2 登入流程狀態機

```
disconnected → connecting（SSH 就緒）→ 等到「請輸入代號…」→ 送出帳號
   → 等到「請輸入您的密碼:」→ 送出密碼
   → 依畫面分支：
       密碼錯誤 / 無此帳號      → loginFailed（不重試）
       請稍後再試 / 頻繁登入     → tooFrequent（冷卻，不自動重試）
       重複登入提示              → 依設定「踢掉其他連線 / 不踢 / 詢問」
       按任意鍵 / 刪除錯誤記錄    → 送出對應按鍵
       主功能表                  → ready
```

### 4.3 重複登入策略

PTT 允許同帳號同時多連線時會詢問是否踢掉其他連線。設定 `vscptt.login.duplicateSession`：

- `ask`（預設）：詢問使用者
- `kick`：踢掉其他連線
- `keep`：不踢掉，本連線繼續

提示文字要寫清楚，因為踢線會讓使用者在手機或其他客戶端被登出。這個提示在 M0 沒有觸發，需要以假傳輸測試分支。

### 4.4 頻率與重連

- 登入失敗或被拒絕後**不自動重試**，等使用者手動操作。
- 意外斷線時自動重連最多 2 次，間隔拉長；重連需要帳密，若沒有儲存則改為提示使用者。
- 重連後不假設還停留在原畫面，一律先 resync。
- 開發與測試時**盡量維持單一長連線**，避免短時間反覆登入。

## 5. 讀取流程

所有流程在指令佇列內執行，每一步都有「預期畫面條件」。

### 5.1 進入看板

1. 回到主選單（resync）
2. 取得看板：優先從「我的最愛」清單用游標選取後按 `→`（已驗證）；以名稱直接進入的做法待 V15 結案
3. 若出現「請按任意鍵繼續」，送出按鍵
4. `waitFor`：第 0 列含該看板名且第 23 列是文章列表的功能提示；逾時或看板不存在則回傳 `false`

### 5.2 看板列表與分頁

1. 進入看板後，游標預設在最新的一般文章；讀取第 3～22 列，拆出欄位，`★` 開頭的列標記為 `isPinned`
2. 往較舊分頁：翻頁後比對新舊兩頁的編號，避免重複或漏掉
3. 每一頁讀完，確認畫面仍是同一個看板的列表

### 5.3 開啟文章

1. 以游標選取該列（方向鍵，或對一般文章用 `#` 加代碼）
2. 按 `Q` 取得 AID 與網址（需要「按任意鍵」關閉訊息框）；已知 `id` 時可略過這一步
3. 按 `→` 開啟，`waitFor` 文章閱讀畫面（第 0 列含 `作者`、第 23 列含 `瀏覽`）

### 5.4 讀取內文

1. 讀取第 0～2 列的作者、標題、時間
2. 以 `PgDn` 逐頁讀取，直到底部顯示 `100%`；每頁以「目前顯示: 第 a~b 行」的行號與前一頁去重
3. 最多翻頁次數設上限，超過就回報錯誤並保留已讀內容
4. 離開文章，回到列表，再確認列表畫面

### 5.5 防止「點 A 顯示 B」與核對規則

這是既有擴充功能出過的問題，對策如下：

1. **每一步都 `waitFor` 預期畫面**，不以固定 `sleep` 判斷成功
2. **識別碼用文章網址／AID**，不用會變動的列表編號
3. **核對方式依文章類型分開**：
   - **一般文章**：開啟後，內文中的 `※ 文章網址` 必須等於 `Q` 取得的網址；不符不回傳、不快取。
   - **置頂文**：列表標題與內文標題**可能不同**（M0 樣本：列表為「本板板規 2017/4/10更新」，內文標題為「2016年1月1日 新板規上路」），因此**不以標題核對**。改為核對：畫面是文章閱讀畫面、看板名相符。這類文章的 `url` 取內文中的網址，並在介面上標示「置頂文，內容可能指向其他文章」。
4. **指令佇列**保證不會有兩個操作交錯
5. **非預期畫面時 resync**，而不是在不確定的狀態下繼續

## 7. 測試策略

| 層級             | 內容                                                                       | 工具                   |
| ---------------- | -------------------------------------------------------------------------- | ---------------------- |
| 畫面解析         | 以 `fixtures/screens` 的 80×24 文字畫面驗證欄位與辨識條件                  | vitest                 |
| terminal         | 餵入位元組，檢查螢幕內容與寬字元對齊                                       | vitest                 |
| waitFor / settle | 假計時器，驗證逾時、提早符合、連續更新                                     | vitest                 |
| commandQueue     | 並行呼叫仍逐一執行；失敗不卡佇列                                           | vitest                 |
| session          | 假傳輸腳本化各登入分支（成功、密碼錯、頻繁登入、重複登入、斷線重連）       | vitest + fakeTransport |
| 核心服務         | 假傳輸端對端：開看板、分頁、取得 AID、開文章、核對失敗時的處理（含置頂文） | vitest + fakeTransport |
| 憑證與隱私       | 掃描日誌輸出與 fixtures，不含密碼、登入來源位址、帳號                      | vitest                 |
| VS Code 層       | 樹狀資料提供者以假的服務測試；整體流程用 F5 手動清單                       | vitest + 手動          |

Fixtures 規則：

- 來源是 M0 擷取的真實畫面（暫存在專案之外），整理成 fixtures 前必須去識別化：移除帳號、登入來源位址、使用者的最愛清單。
- 只使用公開看板的內容，精簡到足以覆蓋案例。
- 不提供「自動錄製並提交」的工具；錄製只在本機手動執行，結果經人工檢查後才加入專案。

必須涵蓋的案例：登入成功與各分支、看板列表（含置頂文與已刪除文章）、文章（含推文、多頁、行號重疊）、AID 訊息框、不存在的看板、非預期插入畫面、斷線、置頂文標題不符。

## 10. 非功能需求

- **相容性**：`engines.vscode` 為 `^1.100.0`，`@types/vscode` 鎖 `1.100.0`。
- **無背景流量**：未登入或未開啟任何看板時，不送出任何指令；保持連線的按鍵是唯一的例外，且可設定。
- **失敗體驗**：任何錯誤不能讓樹狀檢視整個空白；錯誤顯示在節點上並可重試。
- **可診斷**：提供輸出頻道，記錄連線與步驟事件，不含憑證；畫面快照僅在開啟除錯設定時輸出。

## 11. 開發流程約定

- 每個里程碑獨立 commit 與驗證，完成條件逐項通過才進入下一個。
- `pnpm run typecheck`、`lint`、`format:check`、`test`、`build` 全過才 commit。
- 文件中標示「未驗證」的事實，驗證後回寫並附日期；與實測不符時先更新文件。
- 開發時避免短時間內反覆登入真實伺服器；能用假傳輸測的就不連線。
